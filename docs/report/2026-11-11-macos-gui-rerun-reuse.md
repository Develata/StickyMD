# macOS 图形验收的按行记录与复用：设计提案（2026-11-11，待批准）

## 背景

USER 2026-11-11：“以后还是希望能够分批分模块跑记录的自动化测试，不必每次都完全重跑”。本提案只讨论 Phase 16 的 `mac-gui`（Tart 虚拟机里的图形验收）与 USER 人工收据，不涉及 Windows 资格化。

## 已核实的现状

- `mac-gui` 已能分批：`--only` 选行，每次运行把所选行写进 `--out` 下的一份 `mac-gui.json`。证据带 app 可执行文件与 bundle 清单的 SHA-256、系统版本与权限，但**不记录驱动程序身份**，也没有任何东西记住上一次的结果：下一次运行不知道哪些行已经在同一个 app 上通过。
- 人工收据只是报告里的文字（`2026-11-10-macos-vm-acceptance.md` 的“人工收据”节），绑定到 app 可执行文件的 SHA-256。
- Windows 的模块账本（`qualification/module_ledger`）把 `apps/stickymd-mac/` 与 `crates/stickymd-posix/` 列为 `UNQUALIFIED_HOSTS`（`fingerprint.rs:213`）：macOS 的改动不使 Windows 模块失效，账本里也没有 macOS 模块。把它用于 macOS 是改账本，不是直接接入。
- `11` 与 `phase-16.md`：Phase 16 矩阵不是资格化 suite，不产生 exact-candidate 证据。本提案不改变这一点。
- Windows 的既有决定（2026-10-10、10-14）：人工复用的产品域保守取全部产品域；跨候选复用（RC3-B）仍有未解决的设计阻断；输入法场景从不复用。macOS 不应承诺比 Windows 更多。
- 同一台机器、同一份源码的 release 构建可复现：2026-11-11 在干净工作区重新打包，与既有包逐字节相同。所以只改文档或只改工具的提交不会改变 app 的 SHA-256。

## 方案

### 第 1 级（建议现在做）：按行记录，身份相同即复用

- **记录**：每次运行后，每行追加一条记录到 `dist/evidence/mac-gui-ledger/`（只追加，原子写入）：行 ID、结论、运行时间、证据文件路径及其 SHA-256，以及下面的身份键。
- **身份键**：app 可执行文件 SHA-256 + app bundle 清单 SHA-256 + 驱动程序（`stickymd-smoke`）可执行文件 SHA-256 + 环境档案（`sw_vers` 的系统版本与构建号、所需权限，以及由运行者以参数传入的虚拟机镜像 digest：虚拟机内部无法得知自己的镜像）。
- **复用**：`mac-gui --reuse` 时，所选行若在账本中已有同一身份键下的 PASS，就不再运行，结论记为 `REUSED`，并指向原证据及其 SHA-256；FAIL 与 NOT_TESTED 从不复用。另加 `--plan`，只列出将要运行与将要复用的行，不启动任何程序。
- **人工收据**：USER 的确认按行记入同一账本，身份键为 app SHA-256 与“USER 本机桌面 + 系统版本”。app 不变时收据一直有效；app 一变，所有人工行都列入待重新确认的清单。这与 Windows 的保守全产品域一致。
- **从不复用**：I01–I03（输入法）与 R03，与 Windows 一致；W10 这类依赖人眼的行，app 一变就要重看。

收益：只改文档、或只改与产品无关的工具时，app 不变，人工收据全部保留；工具改了，只重跑自动行（虚拟机整套约 25 分钟），人工收据不受影响。产品一改，自动行重跑，人工行需要重新确认，这一点与今天相同。

代价：驱动程序身份按整个 `stickymd-smoke` 计，任何工具改动都会让全部自动行重跑。按场景源文件计更细，但需要证明每个场景只依赖哪些源文件，这一步不做。估计约 300–400 行代码及测试，全部在 `tools/stickymd-smoke`。

### 第 2 级（建议推迟）：按产品模块复用

让人工收据跨产品改动保留，需要为每行声明依赖的产品模块，并证明域闭包；这正是 Windows RC3-B 未解决的问题。建议等 RC3-B 的设计阻断解决后，用同一模型一起做。

## 对规格的影响

- `11` Phase 16 节增加一段：`mac-gui` 的按行记录、身份键与复用规则；从不复用的行。
- `phase-16.md` 的说明句不变（仍不是资格化 suite）。人工行的 `receipt:` 改为同时指向账本记录。
- 治理：账本路径列入现有的证据路径防护。
