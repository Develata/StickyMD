## 执行顺序与身份

提交版本和发布说明后，在隔离 checkout 建立 Source Freeze，保留主工作树的历史候选及收据。
新源码推送后，显式运行 `release.yml`，记录其完整 source SHA、run/attempt/artifact id。
从该 run 下载并独立校验 ZIP、checksum、SBOM、来源、PE 和 portable runtime；
只允许将这份远端产物用于后续 tag/Release 操作，不以本机旧 EXE 或旧 ZIP 替代。

发布说明位于 [0.1.2.md](../release-notes/0.1.2.md)。本次动态 run、hash、下载与校验结果放入
隔离 checkout 的 ignored `dist/evidence/` 及 `tmp/release-v0.1.2-20261002/`，避免回写 source
而改变已冻结身份。

## 对规格的影响与待定处置

不更改 `docs/plan`、readiness 规则、550 ms 门槛、人工状态或历史发布资产。
完整验证完成的路径继续要求 `READY`；若选择在已知缺口下公开，须有本版本明确的风险处置，
保留真实 `NOT_READY`，不得由“创建 Release”推断所有未测项目已经获得豁免。
可以先准备并校验具体候选和发布正文，再根据实际缺口完成最终公开决定。
