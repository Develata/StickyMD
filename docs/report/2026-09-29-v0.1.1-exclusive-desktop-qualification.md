## 确认的工具缺陷与修复

`run_window_resource_measurement` 在首轮隐藏采样之前执行持久化/图片压力循环。
循环将文档改为最后一条图片引用，却未恢复初始文档。因此 `window-resource-0/note/note.md`
只有 **38 bytes**，后续各轮是 **20,480 bytes**，不能称为五次同样本测量。
实际文件长度与 SHA-256 已保存到 `hidden-fixture-review.json`。

修复由同一窗口资源函数持有：运行前保留基线 bytes；压力循环后使用既有原子写入工具恢复，
等待真实 Source 投影与 clean window title 后才进入隐藏预热；每轮隐藏 CPU 采样结束后
逐字节校验文档，并在日志及 JSON measurement 中保留长度。恢复或校验失败返回非零。
新增开销是每轮有限的 20 KiB 文档读取与比较，位于计时采样区间之外；不增加轮询线程或依赖。
泄漏门仍在恢复之前检查，不能用恢复文档掩盖压力循环增长。

该修复只涉及验证工具与投影，不改变产品实现、fixture 内容、门槛、采样次数或工程骨架。
P14-A40 的正式候选状态保持 `NOT TESTED`；修复后的窗口模块定向诊断不替代完整 Resources。

## Resolution — G5 正向图片样本失效与修复（2026-09-29）

后续截图 review 发现，上表 G5 的原始自动化 4/4 成功不能证明正向图片渲染通过：
PNG/JPEG 实际显示了 fallback。以产品解码器复核，旧 PNG 的 IDAT CRC 不正确，
旧 JPEG 缺少 Cb 的 DC Huffman table。旧 WebP/GIF 可由产品解码为 1×1，
不把其他工具对 WebP 的拒绝误报为产品不支持。原始容器头测试不足以发现这些问题。

原始收据、截图和图片 bytes 全部保留；G5 last-success 指针已隔离到本轮目录的
`invalid-g5-last-success.json`，并核对移动前后 SHA-256。`g5-assessment.json` 记录
发现时的初步判定；`g5-fixture-generation.log` 补充产品解码器结果。**完整 G5 资格化
仍未通过**，不得因早先自动化输出成功而复用该记录，也不得把 fallback 当作正常图片。

`ff5aa96` 将四种正向样本替换为共享的 96×64 不透明四色图片：

- G5 使用 `include_bytes!` 读取 render 测试目录的同一份 bytes，删除另一套 base64
  常量和解码代码；写入隔离 portable 目录时使用既有原子写入工具。
- render 集成测试调用实际产品的格式识别、完整准备与预览解码，验证尺寸、保留 bytes、
  四个可见色区和不透明度；JPEG 比较允许有限量化误差。
- 图片文件变更只使 G5 资格化输入指纹失效；回归通过实际文件变更验证。
- CI 显式选择共享图片的 render、smoke 两个使用方及其 Windows 反向依赖，避免
  `include_bytes!` 跨目录引用被 Cargo 依赖图遗漏；模块选择回归已通过。

修复没有新增依赖、产品功能或运行时路径，也没有放宽任何测量门槛。
