## 已核实问题与重现入口

- `preview/pipeline/audit_tests.rs::formula_pressure_keeps_live_layout_bounded_and_preserves_source`
  的 100 个长公式 / 300% 用例明确要求底部出现预算错误。全文布局持有 `Arc<MathRaster>`，
  数学缓存因此不能淘汰；单图分配与总驻留预算还共用同一个 8 MiB 常量。
- Preview 文本先 `Buffer::new` 排版空串再写入实际文字；Source 已使用 `new_empty`。
- 图片在位图 cache lookup 前读取完整编码内容并 hash；同轮重复引用重复执行此路径。
  全文图片尺寸检查同时保护离屏图片变更后的几何与锚点，不能直接删除。
- 表格等分列宽，代码长行采用正文换行；宽内容滚动需统一像素与交互几何。
- 固定字号字形和数学布局缓存需要内存归因，尚未证明实际进程内存超标。

## 可选路径与采用规则

1. 评估 8/16/32/64 MiB 总预算，单公式保护独立。只提高预算不解决全文资源被固定持有，
   不能以有限 fixture 恰好装下作为支持范围内可读性的保证。
2. 保留全文尺寸/映射，将公式位图限定于可见绘制。缓存负责复用，未接纳的单公式可以在
   有界临时工作集中完成绘制后释放。继续使用同一个 Preview worker，不引入任务框架。
3. 图片先按本轮 destination/目标尺寸合并请求，仅保存必要结果索引，不把整篇原编码
   文件保留为新缓存。流式校验须由测量收益决定；外部内容变更语义保持完整。
4. 宽表和代码共享有限的块视口转换；布局各自负责。会话状态、worker 快照、绘制和命中
   同时包含横向偏移，偏移不能改变 DocumentState 或 Durable Config。
5. 文字/数学缓存如确有增长，在原持有者内部实施回收；不建立全局内存协调层。
