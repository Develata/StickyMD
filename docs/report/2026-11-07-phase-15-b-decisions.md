## 依据

**`acknowledge_persisted` 失败路径是防御性缺口。** 它只在回执的 generation 超过文档时失败，而进入这里之前已校验回执与提交时的
generation 相同。正常 worker 的提交来自真实快照，所以只有协议被破坏才可达，尚未复现过普通保存走到这里。

Codex 否决了修复时顺手排队一次外部观察：普通观察可能触发重载或重建，恢复期间又被忽略，不是完整方案；下一次守护保存本来就会重新检查磁盘。

**显示回执只证明窗口可见位。** `IsWindowVisible` 不证明已解除最小化、位于工作区或取得焦点，被遮挡也会返回真。实现时至少同时读回
可见与未最小化，焦点由真实事件证明。

**置顶。** 要把回执接到实际提交点。只加诊断而保留现在的提前 `config.update`，不满足 plan 04。

**定位。** 每个未被取代的逻辑定位恰有一次终结裁决，依据是最终几何观察，不是计时结束或任意移动事件。

## 显示、置顶、定位那一批的桌面观察项

| 场景 | 观察 |
| --- | --- |
| 托盘或第二实例唤醒；隐藏、最小化、收起三种起点 | 可见、最小化、实际矩形、焦点事件；窗口可操作；托盘文字与输入状态同步 |
| 显示或隐藏被拒绝、过期回执 | 不提交相反可见性；隐藏失败不释放缓存；显示失败不恢复输入与 Preview |
| 用户置顶与临时感应置顶 | 原生置顶位、与普通窗口的层级、不抢焦点；配置与临时状态分离 |
| 动画反向、中断、拖动、拔显示器、混合 DPI | 最终矩形与目标一致，旧回执不覆盖新目标，感应条可达，终态只提交一次 |
| 失败后重试 | 等待能结束，同目标能再次申请，不形成永久动画或等待 |
