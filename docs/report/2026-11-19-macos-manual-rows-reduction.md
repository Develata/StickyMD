# 提案：把 macOS 人工验收行减到最少（2026-11-19）

## 结论

建议 Phase 16 的 14 个 macOS 人工行改由三档方式判定：

- **程序自动化（5 行）：** W03、W04、W12、R03、I03 改为 `Automated`，由 `mac-gui` 判定；
- **agent 截图判定（8 行）：** W01、W02、W05、W06、W10、F01、I01、V04 改为新的 `Agent visual`。程序能断言的部分仍由驱动断言；断言不了的视觉部分由驱动在虚拟机里截图，再由一个不带实现上下文的 agent 按事先写定的标准判定；
- **人工（1 行）：** 只剩 I02 微信输入法，因为它只能装在 USER 本机。V05 是 Windows 回归，不在本提案范围。

这会改变验收合同（`docs/acceptance-cases/phase-16.md` 的 Mode）、`11` Phase 16 的账本与出口规则、`07` 对视觉验收的表述，并新增一种 Mode，需要 USER 批准。
驱动、账本与治理检查都要改代码，产品代码不改。建议分两期实施（见“分期”）。

## 背景

- USER（2026-11-19），在锚点合并后被要求逐行重新确认 14 个人工行时：“不要给我这么多人工行，以后验收人工行需要尽可能减少，尽量第一优先程序自动化，其次是 agent 自行截图，最后极少的才是考虑人工验收”。
- 产品输入指纹锚定（[锚定提案](2026-11-17-macos-evidence-anchoring.md)）让收据绑定程序行为的输入；产品代码一改，所有人工行都要重新确认。人工行越多，每次改动的成本越高。
- 2026-11-12 的[提案](2026-11-12-macos-manual-rows-automation.md)只把与显示硬件无关的六行改为 `Automated`（W07、W08、W09、W11、K02、E01），W02–W04 因依赖真实屏幕而保留人工。
  `11` 据此写明“哪些行改为 `Automated`，只限断言与显示硬件无关的行”（`docs/plan/11_testing_and_release.md:294`）。本提案要放宽这条限制。
- 2026-11-19 新身份下的 `mac-gui` 首跑（[VM 验收](2026-11-10-macos-vm-acceptance.md) 末节）之后，`mac-ledger plan` 仍列出 15 个待 USER 确认的行：W01–W06、W10、W12、I01–I03、F01、R03、V04、V05。

## 三档证据

| 档 | 判定者 | 证据 | 绑定 | Mode / 状态 |
| --- | --- | --- | --- | --- |
| 程序自动化 | `mac-gui` 的断言 | `mac-gui.json` | 产品输入指纹、驱动、镜像、系统四项 | `Automated` / `AUTOMATED PASS`（现有） |
| agent 截图判定 | 驱动的断言，加一个不带实现上下文的 agent 对同一次运行截图的判定 | `mac-gui.json`、截图、判定记录 | 同上四项，另加每张截图的 SHA-256 与判定所用模型 | 新增 `Agent visual` / `AGENT PASS` |
| 人工 | USER | 收据 | 产品输入指纹 | `Manual` / `MANUAL PASS`（现有） |

`Agent visual` 行要同时满足两件事才算通过：驱动对该行的断言全部 PASS，且 agent 对该行截图判 PASS。任一项 FAIL 即 FAIL；截图缺失或判不了为 `NOT TESTED`。

## agent 截图判定的做法

1. **截图在同一次运行里由驱动截取**：窗口截图用现有的窗口截取代码（`mac_gui/native/windows.rs`），整屏或切换器用系统 `screencapture`。每张截图的 SHA-256 写进 `mac-gui.json`。
2. **判定标准事先写在验收表**：每个 `Agent visual` 行在 Evidence 前写明“看什么、怎样算通过”，判定时不得改动。
3. **判定者不带实现上下文**：由一个新起的 subagent 判定，只给它行定义、判定标准、截图与对照图，不给代码与本次改动；它对每行返回 PASS、FAIL 或 NOT_TESTED，并写一句理由。
   主会话不改它的结论。判 FAIL 或拿不准时，可再交给 codex（跨模型）看同一组截图。
4. **防止空判**：每行至少有一个能失败的对照（阳性或阴性），例如 W01 的普通 app 必须出现在切换器里、F01 的错字体参考图必须判为不一致。对照不成立时，该行为 `NOT TESTED`。
5. **登记**：`mac-ledger` 新增 `judge` 记录：行、结论、理由、截图哈希、判定模型、产品输入指纹、驱动、镜像、系统。复用规则与自动化行相同：四项一致才复用。
6. **USER 抽查**：截图与判定记录留在 `dist/evidence/`，USER 可以随时抽查；抽查发现判错时，按人工结论追加记录，并修正判定标准。

## 一次性前提（需要 USER）

1. **屏幕录制权限：** 虚拟机里经 SSH 启动的进程还没有屏幕录制权限（2026-11-19 首跑 `mac-gui.json` 的 `permissions.screen_recording` 为 `false`）。
   SIP 开着，不能改 TCC 数据库，要 USER 开一次屏幕共享，在系统设置里给它授权。只做一次，和 2026-11-10 授辅助功能权限一样。
2. **虚拟机系统设置（属于环境配置，按 `mac-test` 的规则需要 USER 同意）：**
   - 加上系统自带的简体拼音输入法（I01；不装第三方软件）；
   - 多建一个桌面（W05、W06）；
   - 关闭软件更新通知。2026-11-19 首跑中，这条常驻通知三次挡住 W09 的点击点。不关的话，驱动在运行前检查屏幕上有没有通知；有就停下，不擅自操作。

## 改动范围

- **合同：**
  - `docs/acceptance-cases/phase-16.md`：上表各行改 Mode，写明判定标准；现有收据保留为“此前”。
  - `11` Phase 16：M2 出口加上 `Agent visual`；账本一节加 `judge` 记录与复用规则；删去“只限断言与显示硬件无关的行”。
  - `07`：第 178、353 行“候选窗位置……继续由人工判定”加上 macOS 的例外：由 agent 截图判定。Windows 的表述不变。
  - `01`：补 `Agent visual` 的术语。
- **治理：** `tools/stickymd-smoke/src/governance.rs` 允许 phase-16 的 `Agent visual` 行为 `AGENT PASS`、`NOT TESTED` 或 `BLOCKED`；phase 16 的就绪检查把它与 `Automated` 同样对待。
- **账本：** `mac_ledger` 增加 `judge` 子命令与记录类型；`plan` 分三类列出：要运行、要判定、要 USER 确认。
- **驱动：** 新增或扩展 W12、R03、I03、W01、W02、W05、W06、W10、F01、I01、V04 的场景与截图；先检查屏幕录制权限，缺少时这些行为 `NOT TESTED`。
- **不改：** 产品代码；Windows；`mac-resources` 与 `mac-latency`。

## 分期

- **第一期：** 不需要第二个桌面与输入法设置的行。W03、W04 只改合同；W12、R03、I03、W01、W02、W10、F01、V04 改驱动与账本。完成后人工行剩 W05、W06、I01、I02。
- **第二期：** 虚拟机设置就绪后，做 W05、W06、I01。完成后人工行只剩 I02。

每期都跑一次 `mac-gui` 与判定，并交 codex 审查驱动与账本的改动。

## 风险与未决

- **真实屏幕：** 截图与断言都在单屏、无刘海、1024×768 点的虚拟机里。刘海遮挡菜单栏图标、真实刷新率下的动画观感、多屏，都不在任何一档的覆盖范围内。
  2026-11-12 正是因此保留了 W02–W04 的人工确认；按本提案，这些风险改为明示的未测范围，不再每次改动都人工确认。
- **撕裂、闪烁、残影（V04）：** 静态截图看不出。方案 B 的呈现路径（`frame_presenter.rs` 等）有改动时，建议把这一项交给 USER 看一次，其余时候不必。
- **合成事件的代表性：** I03 与 I01 依赖 CGEvent 注入是否经过系统的长按和输入法逻辑。阳性对照不成立时，这些行停在 `NOT TESTED`，退回人工或另寻办法，不判 PASS。
- **agent 判定的可靠性：** agent 可能看错，也可能被截图里的意外内容误导。对照、事先写定的标准、新起的判定者与 USER 抽查是缓解办法，不能完全消除。
- **截图授权的稳定性：** 新版 macOS 会定期重新询问屏幕录制授权。弹窗出现时，相关行为 `NOT TESTED`，需要 USER 再授权一次。
- **Phase 17：** N12、R06 与文末留白（M2）的视觉确认也可按同样方式在虚拟机里截图判定；Windows 部分可以用 Windows 资格化已有的截图（G5）。本提案批准后另行提出。
