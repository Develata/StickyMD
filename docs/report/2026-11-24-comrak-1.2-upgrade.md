# 评估：Comrak 从 0.59 升到 1.2（2026-11-24）

## 结论

1. **升到 `=1.2.0`，现在就升。** 锁文件里只有 comrak 一项变化，没有新增或移除的依赖，许可证仍是 BSD-2-Clause。API 改动是 6 处机械修改。
   - **主要理由是一个平方级解析。** 0.59 解析未闭合的 `\(` 要花平方级时间：800 KB 的 `\( a ` 重复，单次解析要 12–31 s，1.2 只要 12–46 ms。
   - **这个解析在 UI 线程上。** `$` 按钮在 UI 线程上同步解析（`crates/stickymd-desktop/src/shell/window_interaction.rs:205`），每次点击至少解析两次。所以在 0.59 下，这样的文本会让窗口卡住数秒到数十秒，预览 worker 也会一样卡住。
   - **另有四个位置缺陷已在上游修好。** StickyMD 原先为它们写了绕行代码，见下文“绕行代码逐项”。
2. **`math_dollars_block` 建议这次不开启。** 它能修多行 `$$` 块，代价是三处新的破坏：未闭合的 `$$` 行会吞掉所在容器的剩余全部内容；现有笔记中的部分 `$$` 会变义；`$` 按钮可能写出变义的结果。详见下文，由 Develata 决定。
3. **等号行补丁（`math_text.rs`）不能删，开不开 `math_dollars_block` 都一样。** 块级公式只认独占一行的 `$$`。`\[…\]`、`$$a…b$$` 和行内公式里的裸 `=` 行仍会被读成 Setext 标题。
4. **绕行代码的处理：**
   - **已删除：** `TableCellSourceMap`。1.2 已按原文报告列号，再修正一次就错了，所以必须删。
   - **建议删除：** 引用定义的位置防护，以及列表项终点列为 0 的修复。它们在 1.2 上都不再触发，30 万例 fuzz 一次也没有触发。是否删除待 Develata 决定。
   - **保留：** 孤立 `\r` 的拒绝、行内结构外扩的校验、`formula_end` 的结束行核对。其中 `formula_end` 已按 1.2 的转义规则更新。

## 背景

- 上游 [kivikakk/comrak#880](https://github.com/kivikakk/comrak/issues/880) 由 StickyMD 提出，由 PR #931 实现，作为可选扩展 `math_dollars_block` 随 1.0.0 发布（2026-11-17）。1.1.0 于 11-20 发布，1.2.0 于 11-23 发布，1.2.0 重写了数学的规格。
- Develata 于 2026-11-24 要求下一版本升到最新的 Comrak 稳定版。2026-11-24 复查 crates.io，最新稳定版仍是 1.2.0。
- 上一次升级的评估见 [Comrak 0.54 → 0.59](2026-11-12-comrak-upgrade-evaluation.md)。当时 USER 选择先升 0.59，并约定 1.0 发布后另行评估第二步。本报告就是第二步。

## 本机实测

环境：Apple Silicon，macOS 27.2，rustc 1.97.1；基于 `84d41da`（main）。

### 探针

探针放在会话 scratchpad 里，不进仓库。它同时依赖 `comrak 0.59.0` 与 `1.2.0`，用与 `markdown_options()` 相同的方言打印 AST 与源码位置，并做 fuzz 和计时。结果：

- **引用定义：** `[a]: http://x\n[b]: http://y\npara **bold** text`。0.59 把段落记为从第 1 行开始，`**bold**` 报在 `1:6-1:13`，也就是 `http://x`；1.2 报在 `3:6-3:13`，正确。
- **表格 `\|`：** `| \|中 $x$ |` 中的公式，0.59 报出的范围是 ` $x`，1.2 报出 `$x$`，正确。
- **列表项终点列 0：** `- one\n- two\n  - deep\n\n1. x` 的第二项，0.59 报 `2:1-4:0`，1.2 报 `2:1-3:8`。
- **跨行链接：** `see [a](http://x\n) end` 的链接，0.59 报到 `1:16`（缺 `)`），1.2 报到 `2:1`。
- **fuzz：** 30 万个随机短文本，字母表覆盖 Markdown 与数学标记。检查三个条件：任一节点终点列为 0；行内节点的最大结束行早于段落（Setext 标题为下划线上一行）的结束行，即 `inlines_shifted` 的判据；链接范围不以 `)`、`]`、`>` 结尾也不等于其文字。0.59 下三项分别出现 1、40、11 次，1.2 下都是 0 次。
- **孤立 `\r`：** 1.2 仍把孤立 `\r` 当作换行，与 0.59 相同；StickyMD 的源码映射只按 `\n` 分行，所以 `$` 按钮在含孤立 `\r` 的文本上放弃，这一点仍然需要。

### 新发现并已修正：`formula_end` 的转义奇偶

- **问题。** 1.2 改了转义规则：`\\` 不再转义它后面的 closer。`math_text.rs` 的 `formula_end` 在多行公式的结束行上找 closer，原来的规则是“第一个前面不是 `\` 的 `$`”和“第一个 `\)`/`\]`”，与 0.59 一致，在 1.2 上就不对了。
- **影响。** 例如 `$a\n\\$ b$`：1.2 在 `\\$` 处闭合，旧逻辑找到的却是后面的 `$`。核对失败后，按 plan 07 的规定，含这种行内公式的整篇文档的等号步骤都会放弃。方向是保守的，但不对。
- **修正。** 新函数 `unescaped_closer_end` 按 1.2 的规格计算：反斜杠转义它后面的一个字节，除非它本身已被转义。
- **测试。** 新增 `phase11b_equals_lines_locate_closers_after_escaped_backslashes`。把实现换回旧逻辑时，这个测试会失败（已实际验证）。

## 对 StickyMD 的行为影响

这些都属于 plan 06 “由 Comrak 决定”的范围。升级后写进 plan 06 #markdown-semantics。

- **位置更准确。** 引用定义之后的段落、表格中 `\|` 之后的内容、以嵌套列表结束的列表项、跨行的链接，现在的位置都正确。依赖位置的 `$` 按钮、预览复制与滚动同步，结果只会更对。
- **`$` 按钮会转换引用定义之后的公式。** 以前这类段落整段跳过，现在正常转换，定义的 title 不动。
- **复制。**
  - 单独选中行内公式时，复制的 TeX 带上换行：`$a\nb$` 复制为 `a\nb`，以前是 `a b`。这与 plan 06 规则 1 的“Comrak 给出的 literal”一致。
  - **新的已知差异：表格单元格以 `\|` 开头时，从 `|` 开始的选区不带那个反斜杠。** 例如在 `| \|x |` 中选 `|x`，复制得到 `|x`，以前是 `\|x`。原因是 1.2 报出的文字节点从 `|` 开始，没有包含反斜杠，而显示文字与这段源码逐字节相同，所以按“一一对应”处理。`\|` 在文字中间时仍会正确地向外取整，例如 `y\|z` 中选 `y|` 得 `y\|z`。修正它需要 StickyMD 再写一段表格专用的位置修正，正是刚删掉的那类代码，所以建议接受；若要改，可以先向上游报告这个位置问题。
- **公式识别的边缘情形。** `$a\\$ b$` 现在是公式 `a\\` 加文字，`\(a\\)b\)` 现在是一个公式。
- **其它预览可见的变化。** task 标记、`c\\|` 单元格、含实体的 email、`_www.example.com_`、`~~a~ *b*`、超过约 50 层的列表，见上表。现有测试中没有因此失败的。

## `math_dollars_block` 的取舍

**它带来的好处：**

- **独占一行的 `$$` 之间，整块都是公式。** 内容里有裸 `=` 行、列表标记、`#`、空行时，不再被 Setext 标题、列表或段落切断（探针核对：`$$\n1\n=\n2\n$$` 是一个 `MathBlock`）。
- **这种块可以打断段落。** 不需要前后空行。不过“段落中间的 display math 自成一行”另有主会话正在做的渲染修正，不开这个扩展也能显示成独立一行。所以开启它的边际好处，主要是内容含空行或 Markdown 标记的多行 `$$` 块。

**它带来的破坏（探针逐项核对）：**

1. **未闭合的 `$$` 行吞掉所在容器的剩余全部内容。**
   - 输入新的公式块时，用户打了 `$$` 和换行，停顿 1 s 后预览刷新，从这里到文档结尾的所有内容（标题、段落）都成为一个公式。例如 `typing\n$$\n\frac{a}{b}\n\n# Next heading\n\nMore prose.` 中，`$$` 之后全部成为 `closed: false` 的 `MathBlock`。
   - 写公式期间每次停顿都会出现。对“打开即写”的草稿纸，这是最常见的路径。
2. **现有笔记会变义。**
   - `$$ x\ny\n$$` 这种开头 `$$` 带内容、结尾 `$$` 独占一行的写法，今天是 display math。开启后，它变成文字 `$$ x y` 加一个空的未闭合块，并且吞掉文档剩余的全部内容。
   - 上游文档把这一点写成规则：独占一行的 `$$` 总是开始块级公式。
3. **`$` 按钮可能写出变义的结果。**
   - `\[ x\n\]` 会被转换成 `$$ x\n$$`，开启后就是上面第 2 条的情形。
   - plan 07 的提交前复核只检查“再点一次不再改动”，不检查转换前后公式是否相同。所以开启前要给按钮加一道语义核对，这是 plan 07 的合同改动。
4. **`\[…\]` 没有块级形式。** AI 输出常用的 `\[\na\n=\nb\n\]` 开启后仍是标题，等号行补丁照样需要。
5. **渲染与复制要补的工作。** `MathBlock` 是新节点，要接入 `BlockNode::DisplayMath`、plan 06 的复制规则（内容范围、侧条）与验收行。未闭合的块还要决定怎么显示，例如按公式错误显示原文：节点有 `closed` 字段，这是显示方式，不改变 Comrak 的语义。

**建议：这次不开启。** 升级保持语义中性，只吸收上游的修复。若以后要开，作为单独的改动，同时做三件事：

- 未闭合的块按公式错误显示原文；
- `$` 按钮比较转换前后的公式节点，不同就拒绝；
- 在发布说明里写明 `$$ x … \n$$` 这类写法的变化。

## 等号行补丁（`math_text.rs`）

- **规定。** plan 07 与 [等号优先的报告](2026-11-12-math-button-equals-first.md) 都规定，上游支持块级 display math 并完成升级后，要重新评估这个补丁是否保留。
- **结论：保留。**
