# 提案：把 VM 已全自动覆盖的 macOS 人工行改为 Automated（2026-11-12）

## 结论

建议把六行改为 `Automated`：W07、W08、W09、W11、K02、E01。这六行的每一项断言都已由 VM 中的 `mac-gui` 自动检查，而且断言的内容与显示硬件无关。改后，它们的状态由账本里与当前程序同一身份的 PASS 决定，每次产品改动后不再需要 USER 逐项人工确认。

W02、W03、W04 虽然也已全自动，但断言的是窗口几何与动画时序，可能受真实屏幕影响（Retina 缩放、刘海、刷新率），建议仍保留人工。其余行维持现状。

这是对验收合同（`docs/acceptance-cases/phase-16.md`）和 `11` Phase 16 出口条件的改动，需要 USER 批准。工具代码不用改。

## 背景

- `11` Phase 16 的 M2 出口写的是“真实桌面项按验收表人工确认”（[11_testing_and_release.md:255](../plan/11_testing_and_release.md)）。人工收据绑定 app 可执行文件的 SHA-256，app 一变就要重新确认（同文件第 265 行）。
- `docs/acceptance-cases/phase-16.md` 中 Mode 为 `Manual` 的行有 19 行（第 38–49、61–64、69–70、79 行）。
- `mac-gui` 已能在 VM 中自动跑其中 13 行，结果按行记入账本，同一身份（app、bundle、驱动、镜像、系统）下的 PASS 可以复用（USER 批准 2026-11-12）。但 Mode 仍是 `Manual`，所以每次产品改动后，这些行仍然要等 USER 的收据。
- USER 2026-11-12 问到这些行是否都是无法自动化的视觉项，并要求起草本提案。

## 可选路径

| 方案 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| A | 九行全自动的都改为 Automated（W02、W03、W04、W07、W08、W09、W11、K02、E01） | 人工项最少 | 失去真实屏幕上的几何与时序确认；W03 的判定还不稳定，会时常出现 FAIL |
| B（建议） | 只改与显示硬件无关的六行（W07、W08、W09、W11、K02、E01） | 去掉每次产品改动都要做的大部分重复确认，又保留真实屏幕上的检查 | 每次产品改动后，W02–W04 仍需人工确认 |
| C | 不改合同，Mode 仍为 Manual；USER 每次看过 VM 自动化结果后，按行认可为收据（像 W12 那样） | 不动合同 | 每次产品改动仍要 USER 介入，只是从操作变为审阅 |

## 方案 B 的具体改动

1. **`docs/acceptance-cases/phase-16.md`**：
   - 六行的 Mode 改为 `Automated`。
   - Evidence 写明：判定来自账本中与当前程序同一身份的 `mac-gui` PASS，并引用最近一次运行。现有收据保留为“此前”。
   - Status 改为 `AUTOMATED PASS`，对应 `4e19774d…` 的 r19、r20。
2. **`docs/plan/11_testing_and_release.md` Phase 16**：
   - M2 出口改为：验收表中 Mode 为 `Manual` 的真实桌面项人工确认；Mode 为 `Automated` 的 macOS 行，由 VM 中的 `mac-gui` 判定，当前程序在账本里须有同一身份的 PASS。
   - 在账本一节补一条“自动化行”：app 变了，这些行要在新身份下重新运行（`mac-ledger plan` 会列出）；没有这样的 PASS 时状态为 `NOT TESTED`。

不需要改的：

- **治理检查**：`governance.rs:1185–1193` 已允许 phase-16 的 `Automated` 行为 `AUTOMATED PASS`、`BLOCKED` 或 `NOT TESTED`。
- **账本**：`mac_ledger/decide.rs:111` 的 `manual_rows` 直接读矩阵的 Mode，改后这六行不再出现在“待 USER 确认”里，而按复用规则出现在“复用”或“要运行”里。
- **驱动与产品**：不改。Windows 不受影响。

## 风险与未决

- **VM 与真实桌面的差异**：这六行的断言不依赖屏幕，但它们都运行在单屏、无刘海的 VM 里。真实桌面独有的问题，比如多屏、刘海遮挡菜单栏里的托盘图标，不在这些行的断言之内，改不改都不会被它们发现。
- **VM 环境变慢**：r16 之后 VM 的保存对话框变慢，原因未查明；E01 已改为等对话框出现再操作。自动化行的结果依赖 VM 环境健康，环境异常时应记为 FAIL 或 NOT_TESTED，并查明原因，不能直接复用旧的 PASS。
- **W03 的判定**：若以后要把 W02–W04 也改为自动，先要让 W03 的时序判定稳定。例如在期限附近加密采样，或把跨期限的样本间隔记为 NOT_TESTED。这需要另行审查。
