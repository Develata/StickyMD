写出失败收据并清理。`exited early 0xffffffff` 是主动中止结果，不是产品自主崩溃。

## 已定位的验证工具缺口与修复

1. Resources 原先只在整轮结束后写 JSON，违反 plan 11 的阶段留证合同。现在在开始及每个
   主要资源场景完成后原子写出 `INCOMPLETE`，携带已完成测量；只有最终完整成功才移除标识。
   checkpoint 写入失败保留一个失败结果，防止最终收尾误将已完成前缀登记为成功。
2. 资源样本使用独立、无公式的 padding；startup 保留原混合文档及 SHA-256
   `cba874eb6af0fce3f6798f6c85122b9be9f745224260a16436b04aa663a2655c`。
   两个 fixture 均显式纳入相应模块输入指纹，避免 fixture 改变后错误复用成功记录。
3. Exact desktop runner 原先仅在整组成功时写收据。本轮 G4 失败后，canonical JSON 仍是
   v0.1.0 的旧收据；身份/指纹检查会拒绝它，但当前失败没有 JSON 留证。现在普通 case 失败
   同样写出本轮所有结果，保留成功项目与错误；失败不更新成功账本。写入也失败时同时报告
   case 错误与留证错误，并保留隔离测试目录。

这些修复只涉及 std-only 验证工具、固定样本和投影，不修改产品行为、工程骨架或发布门槛。
