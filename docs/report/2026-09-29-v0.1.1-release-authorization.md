## 新发现的 CI 失败与修复

`08afc953008d5cb83b11786cf1bd2ed234071be9` 的普通 CI run `36563782945` 中，
Windows headless tests 在两个模块指纹回归失败；相同代码在本地此前通过，Linux CI 通过。
失败分别是仅改 G5 图片却影响 G3 指纹，以及只改资源样本却影响 Performance 指纹。
原始日志来自 job `109390919550`。

复核发现临时指纹流使用 PID + 时间戳命名，测试目录只使用时间戳，并且原先允许复用目录
或截断同名流。并发调用的时钟值相同会造成路径碰撞。固定时间戳、16 个线程的回归在旧
实现中只得到 1 个不同路径，确认碰撞条件；这与 CI 的跨模块干扰现象一致，但远端现场
没有记录每个临时路径，不能据此断言已捕获该次失败的完整时序。

修复增加进程内原子序号，测试目录复用相同路径分配规则并 exclusive create；指纹流也
exclusive create，成功取得所有权后才允许清理。保持流式读取、字节编码、排序和 SHA-256
算法不变，没有产品 runtime 改动、额外依赖或全局串行锁，不关闭并发测试。

固定时钟回归和原有四项指纹回归通过。最终 crate tests、fmt、clippy 及远端检查结果
在后续 Resolution 中记录；失败原件保持不变，不用自动重试掩盖测试问题。
