# 窗口启动失败路径

日期：2026-11-09。基线：`main` `d49c0e1`。状态：等待 USER 批准；批准前不改 `docs/plan` 与代码。

## 背景

Phase 15 的任务文件把这一批列为遗留项：窗口启动阶段的失败以成功退出码结束，多数没有提示。这段代码已经在共享的 `DesktopShell` 里，Debian 宿主会直接使用，而那里连不上显示服务或缺少平台能力比 Windows 常见。

合同只写了启动早期：`02` 的 Failure Paths 要求程序目录不可写时明确提示后退出，目录身份失败时记录并退出。`09` 的 Failure Paths 没有窗口启动阶段的行。

## 现状

下表来自读代码，这些路径没有实际运行过。`apps/stickymd-win` 是 GUI 子系统程序（`main.rs:5`），双击启动时 stderr 不可见。

| 失败 | 位置 | 用户看到 | 托盘 | 退出码 |
| --- | --- | --- | --- | --- |
| 事件循环创建或运行失败 | `main.rs:94-100`、`127-130` | 无 | 尚未创建或随进程结束 | 1 |
| 窗口创建失败 | `handler.rs:47-54` | 无 | 尚未创建 | 0 |
| 绘制表面创建失败 | `handler.rs:60-67` | 无 | 尚未创建 | 0 |
| 没有可用显示器 | `window_runtime.rs:114-117` | 无，文字写进从未显示的状态行 | 尚未创建 | 0 |
| 工具窗口身份，显示前 | `window_runtime.rs:131-140` | 对话框 | 退出前销毁 | 0 |
| 工具窗口身份，显示后 | `window_runtime.rs:158-164` | 对话框 | 随宿主析构 | 0 |
| 透明度无法应用 | `window_runtime.rs:170-173` | 无 | 随宿主析构 | 0 |
| 置顶无法应用 | `window_runtime.rs:175-177`、`197-203` | 无 | 随宿主析构 | 0 |

退出码为 0 是因为 `main.rs:131` 只读 `startup_diagnostics.exit_code()`，它只在诊断运行中可能失败。诊断探针的退出（`render.rs:201`）同样不先销毁托盘。

这些路径没有无窗口测试：`resumed` 需要真实事件循环，`initialize_window_shell` 没有窗口时直接返回。

## 问题

1. 用户双击后什么也看不到，脚本看到的却是成功。
2. 透明度和置顶只影响外观，却终止启动；运行中同样的失败只上报状态行（plan 04 窗口回执）。这与“打开即写”相反。
3. 这一点在 Debian 上会更明显：winit 0.30.13 的 `set_window_level` 在 Wayland 上是空操作，文档标注 Unsupported（`platform_impl/linux/wayland/window/mod.rs:430`）。如果宿主如实报告不支持，现在的逻辑会结束启动。
4. 继续还是终止由壳的控制流隐式决定，文案分散，无法单独测试。

## 可选路径

| 方案 | 内容 | 代价 |
| --- | --- | --- |
| A（建议） | 窗口无法使用或无法安全放置时终止：事件循环、窗口、绘制表面、无显示器、工具窗口身份。透明度、置顶失败时继续，状态行说明 | 透明度、置顶的失败由“结束启动”变为“继续运行”，需要新的测试 |
| B | 全部 7 类都终止，只补提示和退出码 | 行为变化最小，但外观失败仍然阻止打开便签，Debian 要回头再改 |
| C | 只补退出码 | 用户仍然看不到原因，不建议 |

## 建议的合同（方案 A）

`09` 的 Failure Paths 增加两行：

| 场景 | 行为 |
| --- | --- |
| 窗口启动无法完成（事件循环、窗口或绘制表面无法创建，没有可用显示器，工具窗口身份无法建立） | 提示原因，先移除托盘图标，进程以失败退出码结束；笔记不变 |
| 启动时透明度或置顶无法应用 | 窗口继续可用，状态行说明原因；置顶按运行时的失败规则处理，可重试 |

## 实现要点

- `stickymd-app` 新增一个纯模块，给出每种失败的处理（继续或终止）与文案，测试在 Linux 也运行。
- 壳只保留一条终止路径：销毁托盘、提示、记录失败、结束事件循环。诊断探针的退出也先销毁托盘。
- `main.rs` 在壳记录了启动失败时返回失败退出码；事件循环的两处失败改走已有的 `fatal_startup`。
- `initialize_window_shell` 分成显示前后两段，`set_visible` 与 `focus_window` 这两个 winit 调用留在段与段之间；`FakeHost` 记录调用顺序，无窗口测试覆盖每一种失败。
- 不增加依赖。

## 验证

- 无窗口测试：每种失败的处理、托盘先于提示销毁、退出码、继续路径的状态行。Linux 也运行。
- fmt、clippy、产品与 smoke 测试、`phase-00`，桌面预检回归，独立跨模型审查。
- 真实窗口上的这些失败难以制造，保持 `NOT TESTED`，并在验收表写明。
