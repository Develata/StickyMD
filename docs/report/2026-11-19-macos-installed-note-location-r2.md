## USER 的决定

  - 判定“是否在应用程序里”用文件系统身份；

  - 在第一个公开的 macOS 包之前做完这件事。

## 结论

1. **位置决定便签放在哪里，名字决定是哪一张。**
   - **安装版：** `.app` 直接放在 `/Applications` 或 `<家目录>/Applications` 里，便签在 `<家目录>/Library/Application Support/StickyMD/<键>/note/`。键由 app 的名字得出（第 2 节）。
   - **便携版：** 其他任何位置。便签仍在 `.app` 旁边的 `note/`，与现在完全相同，名字不起作用。
2. **判定“在不在应用程序里”，比较的是目录的文件系统身份 `(dev, ino)`，不比较路径字符串。** 判定不出来时提示后退出，绝不因为失败而换到另一个位置。
3. **引入“便签根目录”（Note Root）：即包含 `note/` 的目录。**
   - 便携版的 Note Root 是 Program Directory；安装版的是 `…/StickyMD/<键>/`。
   - 实例锁取在 Note Root 的句柄上，启动时的读写也从这个句柄派生。
   - 运行中目录被移动、替换或删除时，沿用现行合同（`05:62`、P16-S14），不增加新的保证。
4. **加锁前的例外：** 安装版在加锁前可以创建两级空目录，并且每一级都先核验、再进入下一级。这一条要 USER 单独批准。
5. **便携版与安装版之间不自动迁移。** README 写明迁移步骤，目标已有 `note/` 时就停下。
6. **这项改动在第一个公开的 macOS 包之前完成。**
7. **Windows 与 Scoop 不变。**

## 设计

### 1. 判定模式

输入是 canonical 化后的可执行文件路径，与现在 `paths.rs:48` 的做法相同。

1. **是否在 bundle 里：** 不是形如 `<X>/<名>.app/Contents/MacOS/<exe>` 的开发构建，一律是便携版，Program Directory 取可执行文件的父目录，与现在相同。
2. **打开 bundle 的父目录：** 用 `O_DIRECTORY` 打开 bundle 的父目录 `<X>`，取它的 `(dev, ino)`。之后的便携分支直接沿用这个句柄，不再按路径打开。
3. **比较身份：** 候选有两个：`/Applications`，以及从家目录句柄出发的 `Applications`。对每个候选做 `stat`，跟随符号链接与 firmlink。
   - 任一候选与 `<X>` 身份相同，就是安装版。命中优先：另一个候选报错也不影响。
   - 候选不存在、是悬空链接或不是目录（`ENOENT`、`ENOTDIR`），视为不命中。`<X>` 是一个确实存在的目录，不可能等于一个不存在的目标。
   - 都不命中、但有候选因其他原因（如 `EACCES`）查不到，或家目录本身查不到，视为无法判定：提示原因后退出。
   - 都不命中、也没有错误，就是便携版。
4. **范围：**
   - `/System/Applications` 与子文件夹（如 `/Applications/工具/StickyMD.app`）本身都不是候选。没有命中任一候选身份时，属于便携版。
   - 家目录在外置卷上时，那里的 `Applications` 同样是候选。
   - `~/Applications` 是指向别处的有效链接时，按链接目标判定。
5. **家目录的来源：** 取自用户数据库（`getpwuid_r` 查当前 uid），不读 `$HOME`。原因与 `05:139` 不用 `$TMPDIR` 相同：环境变量可被修改。
6. **结构：** 读取文件系统的部分与纯分类函数分开，纯函数单独测试。

### 2. 安装版的键与共享

- **键的取法：** 取 bundle 目录名去掉 `.app`，用实际的目录名，不用 Info.plist；做 Unicode NFC 规范化。键为空、为 `.` 或 `..`、或无法无损转成 UTF-8 时，视为无法判定，提示后退出。
- **共享的判定：** 两个副本是否共用一张便签，由最终的键目录是否是同一个目录决定，因此服从 `Application Support` 所在卷的语义：
  - **规范化：** NFC 之后相同的名字，共用一张。
  - **大小写：** 在默认的大小写不敏感卷上，只差大小写的名字共用一张；在大小写敏感卷上则不共用。
- **复制与改名：**
  - 在访达里“复制”app 得到 `StickyMD copy.app`，或者改名之后，只有当最终的键目录尚不存在时，才会得到一张新的便签。
  - 键目录已经存在时，打开的就是那一张。例如另一个安装位置已经用过 `StickyMD copy`，或者名字只差大小写而卷不区分大小写。
  - 改名后原来那张留在原处。程序察觉不到改名，由 README 说明。
- **子目录名：** 用产品名 `StickyMD`，与 RSS-Reader 一致，便于在访达里找到；不用 bundle ID。

### 3. 便签根目录、加锁与启动

**安装版打开 Note Root：**

1. **起点：** 按路径打开 `<家目录>/Library/Application Support`，它是信任起点。它不存在或不是目录时提示后退出，不去创建。
2. **逐级进入：** 依次处理 `StickyMD`、`<键>` 两级，每一级都按这个顺序：
   - 相对上一级的句柄，用 `O_NOFOLLOW | O_DIRECTORY` 打开；
   - 不存在就用 `mkdirat` 以 `0700` 请求创建（实际权限还受 `umask` 限制）再打开，创建时遇到 `EEXIST` 也重新打开；
   - 对打开的句柄做 `fstat`，核验它是目录、属于当前 uid；
   - 核验通过才进入下一级。不通过就提示后退出，不在其中创建任何东西，也不删除或改动它。
3. **不检查的东西：** 不评估 ACL，也不要求已存在的目录必须是 `0700`。新建的目录是 `0700`，已存在的照原样接受，与便携版不检查目录权限的做法一致。
4. **加锁：** 在 `<键>` 的句柄上取非阻塞 `flock`。

**便携版：** Note Root 就是第 1 节第 2 步打开的 `<X>` 句柄，在它上面取锁。开发构建没有 bundle，用的是可执行文件父目录的句柄。

**两种模式共同的后续步骤：**
- 可写检查、卷检查、`note/` 的创建与打开，都相对已加锁的句柄进行（`DirectoryHandle::open_child`，`crates/stickymd-posix/src/file.rs:137`）。
- 启动阶段的配置、正文与资产读取，与运行期端口一样，从这同一个 `note/` 句柄派生；现在只有运行期端口如此（`adapter.rs:143`）。
- 以下三处与现在相同：
  - 监视器按路径注册，只作提示（P16-S11）；
  - 相对链接仍由宿主按 `note_dir` 定位（`host.rs:99`）；
  - 导出仍然检查目标是否就是工作便签（`export/mod.rs:53`）。

**加锁前的例外：**
- `05:122` 要求第二实例在任何 durable 文件创建前退出。安装版加锁前可能创建 `StickyMD/` 与 `<键>/` 两个空目录，这是对该条的例外，需要 USER 批准。
- 在竞争中输掉锁的实例自己不写任何文件；它可能创建了这两个目录，之后由赢得锁的实例使用。
- 创建后中断，最多留下空目录，下次启动按第 2 步正常接受。

**运行中目录被移动、替换或删除：**
- 不增加新的保证，沿用现行合同：
  - 句柄跟随目录（`05:62`）；
  - `note/` 被换成另一个目录时，资产与配置仍写入原目录（P16-S14）；
  - 被删除后只有正文按路径重建，其余失败直到下次启动（`storage.rs:93-99`）。

### 4. 唤醒

- **互斥：** 由 Note Root 句柄上的 `flock` 保证。这一条是发布门。
- **唤醒是尽力而为：**
  - socket 名取自 Note Root 的 `(dev, ino)`；连接失败时第二实例仍然退出（`instance.rs:51` 起），这时用户看不到窗口被唤起。
  - 系统把 reopen Apple Event 投递给它认定的那个运行中实例，宿主回调只发出“显示”。两个不同名的安装副本同时运行时，在访达里打开其中一个，事件可能到达另一个进程，显示的是另一张便签的窗口。
  - 唤醒错了窗口本身不写盘，但用户接着可能在另一张便签里编辑。这一项只记录观察，不作为发布门（第 8 节），由 USER 判断能否接受。

### 5. 随机化

- 如果 app 实际运行在随机化的只读路径上，就判为便携版，可写检查失败，提示后退出。没有触发随机化时，会作为普通便携版启动，便签写在解压出的文件夹里。
- 提示文字建议改为“请先把 StickyMD.app 拖进“应用程序”，或把整个 StickyMD 文件夹移到别处”，并保留“当前目录不可写”这个前缀。需要同步的地方：
  - 另一分支 `7661364` 的 `mac_gui/translocation.rs` 判定器（检查前缀、原因与窗口）；
  - `mac_gui/tests.rs` 中的完整旧句；
  - 本树的 `tools/manual/macos-r03-translocation.md:35`。

### 6. 迁移说明（README）

- **原则：** 便携版与安装版之间，程序不自动导入，也不删除任何东西。
- **迁移步骤：**
  1. 退出所有用到来源或目标的 StickyMD 副本。
  2. 确认来源是自己的便签。例如曾经直接在 `/Applications` 运行过旧版的人，便签在 `/Applications/note/`，可能是多人共用的。
  3. 把来源的整个 `note/` 另外备份一份。
  4. 只要目标的 `note/` 已经存在（哪怕只有 `.trash/` 或恢复文件），就停下，不复制。由用户自己决定保留哪一份，或另存后再清空目标。
  5. 目标不存在时，把来源的整个 `note/`（含隐藏项）复制过去。如果安装版的 `StickyMD/<键>/` 还不存在，先在访达里手工建好这两级文件夹再复制。不要先启动安装版，否则它会建出 `note/`，触发第 4 步。
  6. 复制中断时，删掉不完整的目标，从第 3 步的备份重来。
- **安装版只在第一个公开包之前完成**，所以公开用户中没有人的便签在 `/Applications/note`；上面第 2 步只关系到之前自己构建运行过的人。
- **同一位置只替换 `.app`：** 安装版用同名的新包替换旧包，继续打开原来的便签。这只对已经采用本规则的版本成立。
- **整个文件夹放进“应用程序”：** 把 `StickyMD/` 整个文件夹放进 `/Applications`，按规则仍是便携版，便签在 `/Applications/StickyMD/note/`。整个替换这个文件夹，会连同其中的 `note/` 一起替换。

### 7. 备份

便签能否从备份恢复，取决于备份的配置、排除规则与最近一次成功的备份，与放在哪种模式无关。本文不作保证。
