## 原生过程与判定

数字框先观察 IME 原生 open status：Source/Search 在编辑前后为开、编辑期间为关；
Preview 保持关闭。物理输入与 config/native alpha 一起核对；字段结束到真正的中文候选
提交之间不调用 profile/mode/IME setter。Search 每次先清掉保留的旧 query，并用负向
复制检查排除旧选区造成的假通过。

组字检查先输入 `shuxu`，尝试数字框聚焦后再输入 `e` 并提交，必须得到与先前真实输入
得到的“数学”词一致的结果。这样，点击若提前提交了前缀，也不能冒充完整组字保持。
在组字开始前准备 1200 × 680 DIP 的自有窗口；Source 的短行和 Split 左侧的 Search
使候选窗与右侧数字框分开。点击仍须经过原生 HWND/光标/焦点检查，不隐藏候选窗或放宽守卫。

Preview 使用 2,000 行中性 ROW 文本，真实按住右侧 thumb，在窗外向上/下及中间移动。
持有手势期间不发送辅助鼠标窗口消息或请求焦点。截图可见尾行 ROW1999；原生 capture、
thumb 列观察及文件不变检查共同判定。失焦后的比较不重新激活测试窗口。

所有当前桌面输入、关联断言与共享渲染夹具采用数学/中文等中性用词；拼音最后一个字符
的编辑测试也同步改为 `e`。历史 USER 提示词存档、旧报告与已封存证据保留原字节。

## 自查发现、失败尝试与修正

1. 最初两个声明集合未包含新增标签，被严格集合测试拒绝；修正声明后通过，未降低比较要求。
2. Search 关闭后按契约保留 query。初版数字框脚本误以为每次为空，且旧正文选区可能使
   复制检查假通过。修正前置条件并增加负向控制；产品代码不改。
3. 初版组字探针先按 Esc，再按 Space，取消了候选后插入空格。改为完成同一次组字后才关弹层。
4. 原生候选窗及其透明边缘覆盖窄窗口控件；输入守卫正确拒绝了其他 HWND。上沿坐标尝试
   仍被拒绝，最终采用组字前加宽布局。所有失败日志、画面和当时 diff 均保留。
5. 自查发现“字母输入后删掉”不足以单独证明 IME 关闭；增加只读原生状态查询，并保留
   后续真实候选提交作为正向证明。两种输入法的增强矩阵均已实测通过。
6. 第 12/13 次运行在进入数字框场景前发现初始 note 多出字符，立即失败并清理自有进程。
   字符来源未确认；未重写 note 消除失败。暂停物理输入、由 USER 确认当前无人使用后，
   相同源码的第 14 次完整矩阵通过；第 15 次增强状态检查也完整通过。不得把早先失败抹去。
