# 提案：macOS 验收按六级阶梯判定（2026-11-19）

本提案取代同日的[人工行缩减提案](2026-11-19-macos-manual-rows-reduction.md)。那份提案经 codex 跨模型审查后暂缓批准（审查要点与处理见末节）。

## 结论

- **原则：** 每一行（必要时拆到行内的子项）用阶梯上第一个可行的方式判定。只有当这一方式能拒绝事先准备的坏样本时，才算可行。
- **目标：** 14 个 macOS 人工行（W01–W06、W10、W12、I01–I03、F01、R03、V04）里，大部分改由程序判定或 agent 判定。
  USER 每次产品改动后要做的，收缩为两项：
  - 集中看一次 V04 的录像，以及低层判定不一致时升级上来的截图；
  - I02 微信输入法的人工验收。
- **先修地基：** 第 0 步先做截图与录屏通道的探测，并修正账本的复用、撤销与判定记录。之后逐行转换，每转一行都要先证明它的检查能拒绝坏样本。
- **需要 USER 批准：** 本提案改动验收合同、`11` 的固定状态词与 Phase 16 规则、`07` 的 macOS 小节、治理检查与账本；`11` 又是 Windows 资格化模块指纹的全局输入（见“影响”）。

## 六级阶梯

USER（2026-11-19）：“能自动化程序完成的优先自动化程序，其次是 agent 自行 操作，次之是 agent截图 check，然后是程序截图人工 check，再然后是录屏人工 check 效果，最后都实现不了才是人工验收”。

| 级 | 判定方式 | 证据 | Mode / 通过状态 |
| --- | --- | --- | --- |
| 1 | 程序断言（`mac-gui` 场景、测试） | `mac-gui.json` | `Automated` / `AUTOMATED PASS` |
| 2 | agent 在虚拟机里自行操作，依据可读的观测判定：AX 树、日志、文件、进程状态 | 操作与观测记录 | `Agent` / `AGENT PASS` |
| 3 | agent 判定程序截下的图 | 截图、对照图、判定记录 | `Agent` / `AGENT PASS` |
| 4 | 程序截图，USER 判定 | 截图、USER 收据 | `Review` / `MANUAL PASS` |
| 5 | 程序录屏，USER 判定效果 | 录像、USER 收据 | `Review` / `MANUAL PASS` |
| 6 | USER 亲手操作并判定 | USER 收据 | `Manual` / `MANUAL PASS` |

- 一行拆成子项时，整行要求每个必需子项都在各自的级别上通过；任一子项 FAIL，整行 FAIL；缺证据为 `NOT TESTED`。
- 第 2、3 级判定拿不准，或两个判定者意见不一致时，不判 PASS，升级到第 4 级，把同一组截图交 USER。
- `Agent`、`Review` 两个 Mode 与 `AGENT PASS` 状态是新增的，只在 phase-16 矩阵中使用。`Review` 的通过仍记为 `MANUAL PASS`，因为判定者是 USER。

## 第 0 步：先修地基

1. **截图与录屏通道的探测。**
   - **前提：** USER 开一次屏幕共享，给经 SSH 启动的进程授屏幕录制权限。2026-11-19 首跑时 `permissions.screen_recording` 为 `false`，经 SSH 运行的 `screencapture` 也失败了。
   - **逐行列出需要的画面：**
     - W02：合成后的桌面边缘，含菜单栏与细条；
     - W01：按住 Cmd+Tab 时的完整切换器；
     - I01：caret 与真实候选窗在同一帧；
     - W10：caret 区域的连续采样；
     - V04：窗口的动态录像。
   - **验证通道能区分好坏：** 每条通道用故意做坏的样本验证，例如遮住细条、隐去候选窗、让光标常亮。分不出来的通道不用。
   - **保存原始输出：** 命令、退出码、权限结果、带本次标记的画面都要留下；SSH 重连之后再验证一次。
   - `CGWindowListCreateImage` 自 macOS 14 弃用，本地 SDK 标为 15 起 obsolete，在 27.2 上的表现以探测结果为准；整屏与录屏用系统 `screencapture`（`-v` 录屏，`-k` 显示点击）。
2. **账本修正**（`tools/stickymd-smoke/src/mac_ledger/`）：
   - **后来的失败阻止复用：** 现在 `decide.rs:51` 会复用最近一次 PASS，即使之后又记过失败，失败只作提示。改为同一身份下后来有 FAIL 时不再复用，要重跑并查原因；历史记录保留。
   - **按批次：** I01、I02、I03、R03 按 `11:293` 从不沿用。改为绑定一个明确的验收批次：同批次内的局部重试不能替代下一批，每批都重跑、重判。
   - **撤销：** USER 抽查推翻某个 PASS 时，追加一条撤销记录，旧 PASS 从此不再复用。
   - **判定记录：** 第 2–5 级的每条判定都要引用同一次运行的 `mac-gui.json` 摘要、行与子项、所用截图或录像的角色与哈希、判定标准的版本、对照图、判定者策略与实际模型。判定标准、对照图或策略一变，旧判定不再复用，按新标准重判。只有缺少所需观察时才要重拍。
3. **判定者：** 第 2、3 级用两个判定者，独立判定：
   - 一个是不带父会话历史的同模型 subagent，一个是 codex（跨模型）；
   - 互相看不到对方的结论，也不告诉它们哪个是对照、哪个是正确答案，对照的顺序打乱；
   - 判定表固定：有效证据下观察到违例即 FAIL；缺证据或无法辨认为 `NOT TESTED`；两者都 PASS 才 PASS；一方 PASS、一方 FAIL 时升级到第 4 级。
   - **校准：** 每条判定标准先用已知的坏图实测，记下误判通过的情况；校准通过才启用。PASS 也纳入 USER 抽查。
4. **SSH 密钥登录：** 把本机公钥写进虚拟机的 `~/.ssh/authorized_keys`，以后开虚拟机不必 USER 输密码。属于虚拟机配置，需要 USER 同意。
5. **屏幕上的干扰：** 2026-11-19 首跑中，常驻的软件更新通知三次挡住 W09 的点击点。运行前检查屏幕上有没有通知，有就停下、记为 `NOT TESTED`；是否关掉这类通知由 USER 决定。

## 风险

- **虚拟机不是真实屏幕：** 单屏、1024×768 点、没有刘海、虚拟显卡。刘海、真实刷新率下的观感、多屏都不在覆盖范围内；多屏按 `02` 本来就未测。这些作为明示的未测范围，请 USER 按行接受。
- **合成输入的代表性：** I01、I03、W01 依赖 CGEvent 是否经过系统的输入法、长按与切换器逻辑。对照或坏样本不成立时，相应行停在 `NOT TESTED`。
- **agent 判定：** 两个判定者也可能对同一张坏图犯同样的错。校准、盲测、升级规则与 USER 抽查能降低风险，不能消除。
- **授权的稳定性：** macOS 可能定期重新询问屏幕录制授权，弹窗会挡住画面；出现时相关子项为 `NOT TESTED`。
