# v0.3.0 候选准备（2026-11-26）

## 背景、范围与已有的 USER 决定

本版本是第一个同时附 Windows x64 与 macOS arm64 两个平台的 Release。下列决定已经作出，本记录只引用，不重新解释：

- **版本号**：USER 2026-11-26 选“0.3.0（推荐）”。workspace 版本已由 #30（`82bf466`）改为 `0.3.0`。
- **两个平台同版发布**（USER 2026-11-19，Phase 18）：获准的附件集合只有“Windows + macOS”六件一种（`11` #release-attachment-set）；
  任一平台的门不过，整个版本不发布；不使用整版例外（`11` #macos-release-gate）。
- **签名**：Windows 维持未做 Authenticode 签名；macOS 维持 ad-hoc，不公证（USER 2026-11-19“维持 ad-hoc”，`02` macOS 宿主）。
- **发布门的收敛**（USER 2026-11-26，[整门复审报告](2026-11-26-m5-gate-review.md)）：完整的跨模型复审与两轮修复之后冻结 R，不再做跨模型复审。
  #31（`96bd2a0`）合入了这些修复。

**范围**是 `v0.2.0..R`，包括：
- Phase 17：复制语义、复制侧条、提示条与文末留白；
- Phase 18：macOS 安装版、公开分发与两平台的发布流水线；
- M5 的 macOS 就绪核对与生产者；
- Comrak 1.2.0；
- 其间的修复。

用户可见的变化见[发布说明](../release-notes/0.3.0.md)。

## 发布提交 R 与构建来源

- **R** 是 `main` 上带着本记录与发布说明的那个提交（本记录所在 PR 的合并提交）。合并之后，R 的 SHA 在下文的 Resolution 中写明。
- **构建来源 S：** 两个平台都在 R 上构建（S = R），本版本不沿用祖先提交上的构建。之后若只有一个平台需要修复而重建，另一个平台按
  `11` #platform-artifact-reuse 判定能否沿用。沿用判定在干净的 R 检出上运行；构建缓存的前提见 `11` #macos-readiness-check“USER 2026-11-26
  增补的前提”。
- **R 之后对矩阵的改动：** 冻结 R 之后，`docs/plan/` 或 `docs/acceptance-cases/` 下的任何改动都会使 Windows 全部资格化模块的收据失效
  （`11` #module-success-ledger）。所以每版的 macOS 发布证据只记在本记录与 ignored 的 `dist/evidence/` 下，不写进验收矩阵（`11` Phase 18 节）。

## 尚未取得、须逐项授权的操作

“开始写”只授权写本记录与发布说明。以下每一项都要 USER 在当时单独授权：

1. 推送本记录所在的分支、开 PR，以及合并它；合并的结果即 R。
2. 对 R 各触发一次 candidate-only 的 `release.yml`（Windows）与 `release-macos.yml`（macOS）。
3. 本机的 macOS 晋升（`release macos-promote`）不需要远端授权。它在干净的 R 检出上运行，下载的是第 2 项产出的 artifact。
4. `mac-test` 虚拟机中的运行：`mac-gui`（含 R03 的 `--zip` 候选包运行）、`mac-resources`、三次 `mac-logout`。虚拟机只在 Develata 说明在键盘前时启动。
5. 真实下载路径 P18-D01–D05。这是第一个公开的 macOS 包，这一项本版不可 waiver。浏览器下载、访达中的移动、Gatekeeper 的放行、口令与 SSH 登录，都是 Develata 的步骤。
6. 人工行的发布用 USER 收据或 waiver（`mac-ledger receipt|waive --release-source <R> --candidate-sha256 <摘要>`），以及 Windows 的 Tier A 与 Tier B 人工项。
7. TAG、DRAFT-RELEASE、PUBLISH 三项晋升操作，各自单独授权。PUBLISH 之前，仓库 ruleset 须禁止更新与删除 `refs/tags/v*`（发布清单第 6 节）。

## 分工

- **macOS 会话：**
  - 本记录与发布说明；
  - 推送与 CI 核验；
  - 两个候选 workflow 的触发；
  - macOS 晋升；

  - `macos-ready`；
  - TAG、DRAFT、PUBLISH 的触发与公开附件的核验。
- **Windows 会话（资格化 clone）：**
  - 在 R 上建立 Source Freeze，记录 `RELEASE-VERSION` 决定；
  - 按 run 与 attempt 下载、校验并 Promote Windows 候选；
  - 运行 `qualification modules` 与需要重跑的模块；
  - 给出 readiness 与人工项清单。

  动态收据留在 Windows clone 的 ignored `dist/evidence/`。由于 `docs/plan/` 与 `docs/acceptance-cases/` 自 v0.2.0 以来都改过，Windows 全部资格化模块都要在 R 上重跑。

## 已知的缺口与风险

- **P18-P04 是 `NOT TESTED`：** 这一行是真实的晋升，要在第 3 项之后才有结果。`phase 18` 的收尾因此以 1 退出。按上文“R 之后对矩阵的改动”，这一行在 R 之后不改写。
- **Phase 17 的两行视觉人工项未测：** P17-N12（提示条的浮层）与 P17-R06（复制侧条）。它们在 Windows 与 macOS 上的观感都还没有人工确认。
- **一个不稳定的性能门：** `math_action` 定义段落的比值上限是 12 倍，历次 CI 实测为 10.6–13.0 倍。#29 合入后它在 `main` 上失败过一次，#31 的 CI 也重跑过一次。
  放宽它是性能门的改动，冻结 R 之后由 USER 决定。在此之前，CI 遇到它就只重跑失败的作业。
- **两项只在本机跑的检查：**
  - CI 的 macOS 作业不运行 `phase 18`，忽略测试归类表的核对只在本机运行 `phase 18` 时生效；
  - 三个只在 Windows 编译的 `reuse_tests`，Windows 的测试分片不运行。
- **整门复审留下的跟进项：** 见[整门复审报告](2026-11-26-m5-gate-review.md)最后一节，都不阻塞本版。

## 失败路径

- **构建或校验失败：** CI、来源、包校验、签名观察或原生运行库失败时，保留日志并定位，不以重建另一个包替代已校验的字节。
- **必要的源码修复：** 产生新的 R 与新的候选，本记录中待授权的操作随之重新绑定。tag 不移动、不覆盖。
  只修一个平台时，另一个平台按 #platform-artifact-reuse 判定能否沿用，并在新的 R 上重跑受影响的门。
- **缺少目标环境或人工观察：** 如实保留 `NOT TESTED`，或在 USER 逐行 waiver 之后记为 `WAIVED`，不改写为通过。
