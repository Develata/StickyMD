### 实施决定（契约内的实现选择）

**M1 提示条**

1. **位置。** 提示状态放在 `stickymd-app` 的新模块，由 `AppSession` 持有。
   Shell 只读取一个提示视图（文字、类别、按钮、标记）来绘制，并把到期与点击交回。
2. **类别由 App 决定。** 每个发出点是一个带类型的提示，类别由 App 内一个穷尽的 `match` 决定。
   - Shared Desktop 与宿主只报告发生了什么，不决定类别（plan 04：Shell 只读）。
   - 删除四条字符串通道：`NoteEffect::Diagnostic`、`AssetStep::Diagnostic`、`ShellEffect::Diagnostic`、`PreviewFollowUp::Report`，
     以及 `DesktopShell.diagnostic`。这样由编译器列出全部发出点，P17-N09 不靠检索。
3. **`SaveState` 的落点。** plan 04 的 `SaveState` 是概念类型，代码由 `PersistenceCoordinator` 承担。
   - `unresolved_failure` 加在它上面。
   - 故障种类取 `FailureKind`（`Failed`、`Unavailable`、`Unsupported`），外加 `WorkerUnavailable`。
   - 回执 generation 不一致与无效回执没有 `FailureKind`，按 `Failed` 处理。
4. **手动保存。** 持久化工作线程合并 note 请求，回执后又以 `Debounce` 重新提交，所以触发方式不能随回执带回。
   - `PersistenceCoordinator` 另记一个待完成的手动保存（目标 generation），只在请求真正提交时设置；
   - 第一次覆盖到该 generation 的保存成功，显示“已保存”并清除；
   - 保存失败也清除它，失败由故障展示呈现。
5. **到期。** `AppSession::next_deadline` 纳入栈顶提示的期限。到期时按栈顶的 id 交回到期回执，状态机按 id 校验。
6. **持久化工作线程停止。**
   - 设置 `unresolved_failure`（`WorkerUnavailable`）。
   - 清除“保留本地”进行中、恢复的 `operation` 与待完成的手动保存。
   - 同时清除 `export_in_flight`。plan 04 只列了前三项；导出走同一个工作线程，不清除的话“正在导出”会一直显示。这是实施补充。
   - 之后的保存请求不再标记进行中，hide 与 quit 屏障立即按失败结算。
     其中用户主动选择的请求（Ctrl+S，以及 F6/F7 中需要持久化的选项）立即得到重要提醒“持久化不可用”。
7. **呈现。**
   - Shared Desktop 在 Search 浮层之后、工具栏之前，在窗口底部画 34 窗口 DIP 的提示条；文字用 Source projection 的 UI 文字绘制，与 Search 相同。
   - 删除 Source 的诊断条绘制与它在绘制键中的位置。
   - 提示变化只请求整帧重绘：重新 blit 已缓存的窗格像素，不触发 Source 绘制，也不提交 Preview 任务。
   - 光标的局部重绘区域与提示条相交时，改走整帧重绘。
8. **点击。**
   - 按钮命中后派发与 F6/F7 相同的决定。提示条浮在内容之上，它区域内的按下都归它，不穿透到下面的 Search、窗格或链接；滚轮照常滚动下面的窗格。
   - 工具栏标记的命中区为标记矩形向外扩展，点击开始一段新的故障展示。
9. **启动警告。** 宿主把全部启动警告交给 App，每条一个重要提醒；现状只保留最后一条。

**M3 复制语义**

1. **数据从哪来。**
   - 构建渲染树时，`copy::OutlineBuilder` 记下被拍平的结构：块的嵌套与各块覆盖的渲染块（叶块），以及每个叶块的行内结构（源码范围、可见内容范围、父结构）。
     大纲随渲染树以 `Arc` 共享，重排不重建。
   - 排版拼显示文字时，`copy::SelectionText` 每段记一条来源：显示范围、源码范围与类别（文字、行内代码、公式、图片、代码块、列表标记）。
     长文字在排版中被拆成单词，这些段按相同的源码范围合并回来。
   - 帧的显示投影持有显示文字、复制映射与源码快照；快照是解析时的同一份 `Arc<str>`。
2. **端点解析。** 显示位置是两个字节之间的边界：起点绑定其后的字节，终点绑定其前的字节，所以任一边界都有确定结果。
   - 块之间的换行、表格的制表符与换行、空单元格都不对应源码：起点移到同一叶块中下一段的源码起点，终点移回上一段的源码终点；叶块内没有可用的段时取该块的源码起点。
   - 起点落在列表标记上，吸附到所属列表项的起点，再按块边缘规则外扩；终点落在列表标记上，取所属列表项的起点。
   - 文字段只在显示文字与源码切片逐字节相同时逐字节映射；行内代码与反引号之间的内容比较。判断在复制时只对端点所在的段做，不在构建时做。
   - 代码块与 Raw HTML 块按行映射：显示的第 k 行应是该块源码第 k 行（围栏块从开围栏的下一行算起）的后缀；不是时端点取该行的边界。
     围栏块是否闭合以 Comrak 的 `closed` 为准，复制侧不自行判断。
   - 规则 6 取整或规则 3 外扩之后，端点落在叶块第一段文字的起点之前（或最后一段文字的终点之后）时，按规则 2 再做块边缘外扩。
3. **结果形式。** 规则 1 给出对象自身的文本；规则 2、3 给出源码快照中递增、不相交的区间，由帧拼成字符串。区间越界或不在 UTF-8 边界时不复制。
4. **空选区** 复制空字符串，与改动前相同。
5. **渲染失败的公式** 仍是公式对象：降级为文字绘制时保留公式信息，规则 1 照常复制 TeX。
   没有源码范围的对象（公式、图片、代码块）也保留记录，规则 1 只用它的显示文字或 TeX；端点映射跳过它们。
6. **Comrak 0.59 报出终点列 0 的列表项。** 列表项的最后一个子块是嵌套列表、其后有空行时，观测到 Comrak 交出的位置终点列为 0（`- one\n- two\n  - deep\n\n1. x` 的第二项是 `2:1-4:0`），
   尽管它对列表后代有修正终点列 0 的步骤（`fix_zero_end_columns`）；原因未查明。解析器原先因此丢掉该项的源码范围。
   现在按那个修正赋值的规则，取最后一个子块的终点（`parser.rs` 的 `zero_end_item_range`）。复制侧另有兜底：块没有源码范围时，取它第一个有范围的叶块的起点。
7. **自动链接（USER 决定 2026-11-17：“然后自动链接可以按你的建议来做。”）。** plan 06 的外扩校验原先只接受以 `)` 或 `]` 结束的链接，
   选区碰到自动链接（包括恰好选中整条 `<url>`）就吸附到整段。现在 `<…>` 以自己的 `<`、`>` 定界，裸 URL 与裸邮箱的范围须恰好等于显示文字，
   切开时复制整条链接（`f23a901`，plan 06 规则 3 已补写）。Comrak 0.59 报的自动链接范围正是如此，末尾标点不算在链接内。
8. **Shell。** Ctrl+C 读显示帧的 `copy_text`。映射失败时显示提醒“复制失败：选区无法对应到源码，剪贴板未改动。”（新增 `Notice::CopyUnmapped`，归入可立即重试的失败）。
   `PreviewFrame::copy_selection` 改名为 `selected_text`，只读选区覆盖的显示文字，供测试使用。

**M4 复制侧条：**

1. **目标与复制在 Render。** `PreviewFrame::copy_rails`、`copy_rail_at`、`copy_rail_text` 是 App 读侧条的全部入口（`crates/stickymd-render/src/preview/copy_rail.rs`）。
   - 每帧绘制时从可见块的代码、数学背景装饰生成，与横向滚动目标同一时机；侧条不进排版。
   - 每根侧条带帧的 generation 与 render block 序号；帧只认自己的侧条，别的帧（generation、宽度或缩放不同）复制不出东西。
2. **降级在 Render 判定。** 整根落在 `0..width_px` 内才产出。纵向滚动条在窗格右侧之外的槽里，所以窗格内容区即帧宽。
   纵向按视口裁剪：块露出多少，侧条露出多少。
3. **只按规则 1 复制。** 新增 `CopyMap::object`，只调用规则 1；不像 `resolve` 那样在规则 1 不成立时退到切片，因此不会带出围栏。
   - 内容是 Comrak 的 literal：代码块含末行换行（与全选单个代码块的结果相同），多行 `$$` 公式含内侧换行。
   - 空代码块复制空字符串；`WriteClipboard` 对空串不写剪贴板、不提示，与 Ctrl+C 空选区相同。
   - 只为能按规则 1 取到内容的对象产出侧条，所以点击不会失败，不需要新的失败提示（“选区无法对应到源码”的措辞不适用于侧条）。
4. **绘制在显示帧之上。** Render 提供绘制函数与配色（`PreviewFrame::paint_copy_rails`），Shell 在贴出帧之后、Search 与提示条之前调用。
   不画进帧像素的原因：帧由 preview worker 重绘，`request_preview_paint` 在帧落后于文档时拒绝重绘。
   若侧条画在帧里，悬停在落后帧上不会变化，而且每次进出都要等一次 worker 往返。
5. **命中针对当前显示帧。** 即已装入窗格、尺寸与窗格一致的帧（plan 06 规则 4，USER 决定 2026-11-17）；不像开始选区那样要求帧的 generation 是最新的（规则 4）。
   按下时就从该帧取出复制内容，所以松开之前到达的新帧不改变它。
6. **交互。**
   - 左键按下时，侧条命中先于开始选区；按下同样把键盘焦点交给 Preview，选区不变。
   - 按下后移动达到 3 DIP（按 Shell 的 DPI）即为拖动，既不复制也不选。阈值在其他移动处理之前更新，所以早返回的处理（滚动条、横向轨道）遮不住它。
   - 松开不论落在哪里，都先由侧条的按下处理。没有等到松开的旧按下，在下一次左键按下时丢弃，不会被之后的松开复制。
7. **悬停按需计算。** 条件：指针在窗口内，没有其他拖动，不在工具栏、弹出层、提示条或滚动条槽上。
   只记住上一帧画成悬停的那根侧条，变化时请求一次完整重绘；光标为手形。新帧、滚动与布局变化在下一次绘制时自然反映。
8. **外观暂定。** 宽 8 内容 DIP；Light 静止 `(224, 220, 209)`、悬停 `(198, 193, 180)`，Dark 静止 `(64, 63, 59)`、悬停 `(92, 91, 86)`。均待 R06 视觉验收后固定。
