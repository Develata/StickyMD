# StickyMD 0.3.0

从本版本起，同一个 Release 同时附 Windows x64 与 macOS arm64（Apple Silicon）两个平台的包，两边一起发布。macOS 版第一次提供下载，
分安装版与便携版。两个平台都新增了：
- 预览中的复制规则与复制侧条；
- 窗口底部的提示条；
- 预览的文末留白。

Markdown 解析器升级到 Comrak 1.2.0。

## macOS（第一次提供下载）

- **下载与要求：** 下载 `StickyMD-0.3.0-macos-arm64-portable.zip`，解压得到 `StickyMD/` 文件夹。需要 macOS 27 及以上、Apple Silicon；
  更早的 macOS 与 Intel Mac 不提供，也未验收。
- **签名：** 程序为 ad-hoc 签名，未经公证。若 macOS 拦下第一次打开，到“系统设置 → 隐私与安全性”点“仍要打开”并确认。
  实际的对话框与步骤以本版本的下载路径验收为准，发布时补全。
- **安装版（推荐）：** 把 `StickyMD.app` 拖进“应用程序”（`/Applications` 或个人的 `~/Applications`）再打开。
  - 便签存在 `~/Library/Application Support/StickyMD/StickyMD/note/`。
  - 以后用同名的新版本替换 app，打开的仍是这张便签。
  - 需要另一张便签时，复制 app 并改成另一个名字（例如 `StickyMD 数学.app`）：这个名字的便签目录还不存在，就得到新的一张；已经存在，就打开那一张。
- **便携版：** 用访达把整个 `StickyMD/` 文件夹移到别处再打开。便签在 app 旁边的 `note/`，与 Windows 一样，复制整个文件夹即得到第二张便签。
- **在解压出的原地直接打开时，** 系统可能把 app 放到只读的随机位置运行。这时程序提示“当前目录不可写，请先把 StickyMD.app 拖进“应用程序”，
  或把整个 StickyMD 文件夹移到别处。”并退出，下载目录与便签目录都没有写入。
- **从 0.2.0 的本机构建升级：** 0.2.0 没有提供 macOS 下载。若你曾把本机构建的 app 直接放在“应用程序”里运行，旧便签在 `/Applications/note/`。
  它在那里是便携模式。请按包内 README 中“在便携版与安装版之间搬运便签”一段手工迁移；程序不会自动搬运便签。

## 预览中的复制

- **复制范围由选区的起点和终点决定：**
  - 只选中一个公式，得到不带 `$` 等分隔符的公式本身；
  - 只选中代码块里的几行，得到这几行代码，不带围栏；
  - 选得更多时，得到这段内容的 Markdown 原文，粗体、标题、链接、列表符号等都保留。
- **符号的补齐：** 从标题或引用的第一个字开始选，会带上 `#`、`>` 前缀；从项目符号开始选，才带上 `-`。
  选区切开粗体、链接等行内结构时，复制整个结构。
- **源码视图同一规则：** 符号本来就看得见，选到哪里复制到哪里。
- **复制侧条：** 代码块（含 Raw HTML 块）与块级公式的右侧有一根与块等高的淡色细条。
  - 点它复制整个代码块或公式，复制公式时不带分隔符。
  - 鼠标移上去时变亮，按住拖动不会复制。
  - 窗口太窄或缩放太大、放不下时不显示。

## 提示条

- **位置与时长：** 提示显示在窗口底部，三种视图都看得到。
  - 成功（例如“已复制”、手动保存后的“已保存”）3 秒后消失；
  - 一般提醒 5 秒；
  - 重要提醒 30 秒。
- **保存失败：** 自动保存不再显示提示；保存失败会一直提醒，直到之后的保存成功。
  - 失败原因显示 30 秒，之后在工具栏留一个标记，点它可以再看 30 秒。
- **需要选择的提示：** 例如“文件已在外部修改”，它们不会自动消失，直到你按 F6/F7 或点按钮做出选择。
- **启动时的失败：** 等待恢复选择时出现的启动失败不再弹出对话框，改为显示在恢复选择之上，恢复的按钮仍然保留。
- **失败标记：** 工具栏在任何宽度下都为它留出位置，标记总能点到，也不会画在关闭按钮上。
- **叠放：** 失败提示不会被后来的成功提示盖住，也不会被丢掉。

## 预览的文末留白

- 预览可以滚过文末半屏，让最后一行离开提示条；内容加上提示条仍放得下一屏时，不会因此可以滚动。源码视图不加留白。

## 公式与解析

- **解析器：** Markdown 解析器从 Comrak 0.59 升级到 1.2.0。
  - 旧版本在解析很长的、未闭合的 `\(` 文本时要数秒到数十秒，窗口会卡住；新版本只要几十毫秒。
- **段落中的块级公式：** 段落中间的 `$$…$$` 块级公式按块级单独成行显示。
- **段落中的行内图片：** 按它最终所在的位置读取，段落靠后、尚未进入可见范围的图片不再在第一帧就读取与解码。
- **`$` 按钮：**
  - 把 `\(…\)`、`\[…\]` 改写为标准的 `$…$`、`$$…$$` 写法；
  - 内侧带空格、本来显示为普通文字的 `$ … $`，也改写为 `$…$`。这只在同一行恰好两个 `$`、内容像公式时才改，所以 `$ 5 和 $ 10` 这类价格不变；
  - 改写之后把结果再读一遍，某个公式改写后不再是同一个公式时，只有它保留原样；
  - 公式以外的内容因此会变时，这次点击不做任何改动；
  - 文中只要有一个后面不接换行的回车符（孤立的 `\r`），按钮就对整篇不做任何改动。

## 发布与验证流程

- **构建来源：** 两个平台各有自己的构建来源提交，发布说明分别写明。
- **沿用：** 某一平台的构建输入在两个提交之间没有变化时，可以沿用较早提交上的构建，不重新构建。
- **macOS 发布门：** 本版本起，macOS 包也要通过一道逐行判定的发布门。它核对的有：
  - 候选包本身；
  - 在发布提交上运行的源码测试；
  - 虚拟机中的程序验收与资源测量；
  - 维护者的人工收据。

  这道门在冻结源码之前做过一次完整的跨模型复审，并据此修复。

## 验证范围

本说明在 Source Freeze 之前写成，不含两个平台候选包的哈希与验收结果；发布时按实际结果补全，未执行的项目保持 `NOT TESTED`。
具体范围与验证顺序见[本次候选准备记录](../report/2026-11-26-v0.3.0-candidate-preparation.md)。

## 运行与升级

**Windows：**
- 下载 `StickyMD-0.3.0-windows-x64-portable.zip`，解压后运行 `StickyMD.exe`。适用于 Windows 11 x64，portable，无安装器。
- 程序未做 Authenticode 签名，Windows 可能显示未知发布者或信誉提示。
- 升级前保存并退出旧实例，备份原目录的 `note/`。
- Windows 三件附件的文件名与 0.2.0 相同，用 Scoop 安装的方式不变。

**macOS：** 见上文 macOS 一节。

**附件与核对：**
- 发布附件共六件，每个平台三件：便携 ZIP、checksum 文件与 SBOM。
  - Windows：`SHA256SUMS.txt`、`SBOM.spdx.json`；
  - macOS：`SHA256SUMS-macos-arm64.txt`、`SBOM-macos-arm64.spdx.json`。
- 请从官方 Release 下载，并核对 checksum 与来源证明；无需关闭系统防护。
  - Windows：`Get-FileHash -Algorithm SHA256`；
  - macOS：`shasum -a 256`。
